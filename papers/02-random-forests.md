When considering the relationship between the strength of an individual tree and the correlation between them, what is relevant is diversity between the trees.  If a thousand trees are all very strong, but nearly identical; that is they all see the same data and make the same decisions, then they will likely make the same mistakes too.  "Voting" across those thousand trees doesn't help much in adjusting the error.  The part we can focus on is that one thousand "weaker" trees would make different mistakes.  A few trees might misclassify an observation, but the rest could get the classification correct.  The errors could cancel each other out when the predictions are aggregated amonst the thousand trees.  The tradeoff being more randomness means weaker individual trees, but less correlation between the trees.  Less randomness means stronger individual trees, but potentially more correlated errors.

If I were evaluating how sensitive the model's performance was to different training and test splits or if I were tuning hyperparameters, I would insist on cross validation.  If I wanted a clean estimate of performance on data that was never involved in the model development, or if I were going to apply the model to data from "the future", I would insist on a separate test set.  For example, as a cybersecurity professional, if I were predicitng whether a cybersecurity alert was malicious, I would want a separate test set consisting of data from a later time period than the data used to train the model.  If the model was trained on data from January to July, I would want to test it on newer alerts to see how well it performs on data it has never seen.  That is, test how the model handles "future" data, not randomly held-out observations.
